# Exact matching boundaries

Accuracy work is paused. The public baseline provides canonical source and the
original-toolchain build. Historical matching tools, function records, receipts
and evidence remain local; cleanup does not renew or discard their results.

A function-code match requires canonical C++ compiled with the selected VC7,
SDK and library inputs, compared with the identity-checked original F3.exe.
Include every original function chunk, owned shared tail and exception-handling
contribution. Resolve every relocation to an evidenced target. Unresolved
operands or incomplete scope are candidates, not exact results.

Do not mask, crop, patch or synthesize compiler output. Preserve actual calling
conventions, layouts, ownership, failure behavior and original bugs. Reuse real
third-party libraries and keep dependency code separate from proprietary credit.

The existing tools/matching_pe.py reader provides PE/COFF bounds from pinned
chunks or compiler procedure records. A whole COMDAT's padded size is not a
function bound. Use the retained compiler/linker comparison tools when accuracy
work is explicitly resumed; do not introduce another verification framework.

Code equality, complete class ABI/RTTI, behavior and whole linked-image equality
are different claims. A build or source association proves none of those by
itself. Keep current exact results, historical results needing recheck, measured
mismatches and untested code separate. Do not describe stale input pins as a
new binary regression or upgrade old partial results to complete claims.
