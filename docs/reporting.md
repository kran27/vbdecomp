# Reporting source and accuracy

The public baseline is a reconstruction in progress. State which toolchain and
configuration built, what was compared or exercised, and the limits of the
result. Compilation/linking is not exactness or evidence of runtime correctness.

Historical function records, accepted receipts and completed progress snapshots
remain local and immutable. They are not build prerequisites or a renewal queue.
A saved status must retain its timestamp and must not be presented as newly
validated. Repository cleanup creates no new exact-match credit.

When accuracy work is resumed, record the selected original address, source
symbol, compiler options, complete comparison scope and remaining blocker.
Pin actual source/header/toolchain/object/comparison inputs per function.
Reporting files, instructions and whole registries are not binary inputs.

Use the retained local receipt tools for completed comparisons. Register results
promptly without a project-wide audit or extra review ceremony. Keep restored
historical proofs separate from new matches and deduplicate overlapping byte
ranges and original addresses. Unavailable evidence stays explicitly unavailable.
