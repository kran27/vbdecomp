# Van Buren Decompilation

A work-in-progress decompilation of the original Fallout: Van Buren demo.
The goal is to produce a result as close as possible to the original source code.
This is not yet an exact or complete reproduction.

The main branch of this repo houses the "baseline" decompilation, which intentionally
keeps original bugs, and only uses the legacy toolchain and dependencies.
Fixes and modernizations live in the `modern-msvc` branch. That may branch off into another repo
at some point, but for now it's easiest to keep them linked while accuracy work continue on the baseline.

### Current status

Source accounting checked 2026-11-14 UTC.

The catalog lists 10,110 functions from the original executable. Of these, 9,949
(98.4%) have been classified by where they came from: 5,242 belong to the game or
engine, 4,115 to libraries, and 592 are supporting code generated by the compiler.
The origin of the remaining 161 is unresolved. **This classification does not
measure how much of the game has been reconstructed.**

For the 5,242 game/engine entries, the table below describes how each original
function has been connected to the reconstructed source. Entries can share an
implementation or represent operations the compiler generates automatically;
each entry does not necessarily need a separate handwritten function.

| What has been located in the source | Entries |
| --- | ---: |
| Implementation located, with no gap currently flagged | 4,813 |
| Implementation located, but marked as partial | 27 |
| Implementation present, but the source parser still reports uncertainty | 11 |
| Operation supplied implicitly or generated by the compiler | 138 |
| Connection to source missing, incomplete or still needing review | 253 |

Locating an implementation does not prove that it is complete or correct.
**These are confirmed gaps, and are not necessarily representative of remaining work.**
See [implementation status](docs/implementation-status.md) for the review's scope and
unresolved questions.

As of 2026-11-12, at least 3,447 game/engine functions had recorded verification
that their compiled code matched the original exactly.

## Build

The original Visual C++ 7.0 compiler and runtime, November 2001 Platform SDK,
and DirectX 8.1 SDK are currently used, and no support is given for modern toolchains.
Game and engine sources use C++98; Small and zlib compile as C.

This project expects Windows, PowerShell and Python 3.11 or newer. Setup uses `curl`
and a RAR-capable `tar`, both supplied with current Windows. These are used to gather
and run the original dependencies.

### Instructions

First, run the following:

```powershell
./scripts/Setup.ps1
```

This downloads and verifies the SDK/tool bundle and the original demo under `deps/`,
generates import libraries from its original DLLs, and builds Release. Pass `-DependencyBundle` for an already downloaded dependency ZIP,
`-GameArchive` for an already downloaded demo archive, or
`-GameRoot` to use an existing original installation without modifying it.

After setup, building is done by running

```powershell
./scripts/Build.ps1 -Configuration Release
```

The build script reads [explicit target lists](config/build-targets.json) directly.
See [build details](docs/build.md) for more information.

For drop-in use, copy `build/legacy-vc7/release/F3-openvb.exe` beside the original
demo's `F3.exe`. Start it with that demo directory as the working directory;
it uses the original assets and DLLs directly. Settings and saves
use `Documents/F3-openvb/`.

- Game: `repos/openvb/src`; engine: `repos/openvb/openje/src`.
- Vendored Small: `src/dependencies/small-script`, from
  [kran27/small-script](https://github.com/kran27/small-script), including the F3
